# 工作树操作规范(appendix/worktree.md)

环境未安装 worktree 类技能时,按本规范执行工作树流程。若已安装对应技能,以该技能为准。

## 建树

1. `git worktree add <工作树路径> -b <新分支>`——路径与分支名带时间戳保证唯一;**并行多树必须串行创建**(时间戳天然错开);
2. 工作树路径与分支名写入派发提示词/QA 文档头部,执行者按给定路径进入;
3. **复制清单**:运行/测试需要 gitignore 资产(`.env`、本地数据库、上传目录等)时,从主工作区复制进树(仅本地磁盘两目录间复制,不外发):源路径 → 树内路径逐项登记;复制件**不 `git add`、不提交**;清单同时是收尾删除副本的依据;
4. 主工作区对这些文件始终只读;复制进树是执行者对主工作区唯一的写例外。

## 树内开发

1. 一切修改限工作树内;提交只打工作树分支;
2. 提交信息遵循项目规则;
3. 对主工作区与 `.scratch/`(票据目录,如有)一律只读。

## 收尾(验收通过后,管理员执行)

1. **先**按复制清单逐项删除工作树内全部副本(不先删,`git worktree remove` 会因"不干净"失败;且敏感内容必须随树清除、不得残留);
2. `git worktree remove <工作树路径>`;
3. 检查并清理分支 upstream 后删分支;
4. `git worktree prune`。

## 合并(验收通过后,管理员在主工作区执行)

1. 优先 `git merge --ff-only`;不能快进则 `--no-ff`;
2. 冲突不自行解决,列冲突文件清单交用户;
3. 多树(多票/多单元)合并必须逐个串行。
